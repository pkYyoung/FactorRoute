## 公开文件

- `config.json`：日期、数据版本、权重、资格条件和成本假设，改权重改这里。
- `report.md`：本周实现、研究依据、验证与限制，不能把回测写成实际成绩。
- `selected.csv`：代码、公司、行业、当前评分、最终排名和股票内部目标权重。
- `metrics.json`、`equity.png`：归一化净值、指标、分期结果及图，不含账户金额。

原始行情、完整因子、所有调参输出、日志和私有交易计划不提交。本仓库不承诺分发供应商数据。

## 队友首次复现

1. 按根README创建环境，安装 `python -m pip install -e '.[yfinance]'`。
2. 有本地快照则用 `--stage research`；首次获取则用 `--stage all`。
3. 查看终端打印的 `outputs/weekly/` 结果，核对实际数据截止日和质量记录。
4. 同版本本地快照可做逐点复算；供应商重新下载数据会修订，数值不一定完全相同。

## 下一周怎么更新

复制本周 `config.json` 到新周一命名的目录。填写新的week、signal_date、reported_on及download_end_exclusive，保持已经冻结的评分方法和权重；end不包含当天。不要每周无条件重选“历史最优”参数。

用 `scripts/run_weekly.py --config 新周配置 --stage all` 下载并研究；保存新快照路径，后续离线用research。检查质量、公司去重、行业和事件风险，明确本周是否改变规则。

确认要归档后在同一研究命令加 `--publish`，再编写并复核周报。已有精选结果默认拒绝覆盖；同周追加试验保存在本地outputs，对正式修订应保留Git变更说明。`--publish`不会提交或推送Git。

如果使用 `--study-weights`，保留候选集合、训练/复核区间、筛选标准、已查看数据等信息；结果只作研究，不会自动写回配置。真正改规则时另做验证并说明生效周。

最后仅提交代码变化和该周配置、报告及精选成果，正常推送main；不要 `git add .` 把本地数据一起加入。
