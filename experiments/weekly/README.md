## 归档规则

- 每周只保留一份 `report.md`，记录信号日、行情截止日、实际或计划执行日、研究结论和复现命令。
- 周根的 `config.json` 专用于 `scripts/run_weekly.py`，沿用主程序格式。精选名单、指标和净值图分别用 `selected.csv`、`metrics.json`、`equity.png`。
- 独立实验放在当周的 `research/<实验用途>/`。同类实验跨周沿用相对路径和文件名。主入口用 `run.py`，独立配置用 `config.json`，已有独立验证入口用 `verify.py`。补价和验收分别用 `download.py` 和 `audit.py`。
- 配置、辅助代码和实验专属精选成果随实验归档。多个实验共用的代码只保留一份，放在当周 `research/` 内。目录和文件按实际用途创建。
- 完整行情、回测输出、调参检查点、临时脚本和过程报告留在本地 `outputs/weekly/<周一日期>/`。

## 队友首次复现

1. 按根README创建环境，安装 `python -m pip install -e '.[yfinance]'`。
2. 有本地快照则用 `--stage research`；首次获取则用 `--stage all`。
3. 查看终端打印的 `outputs/weekly/` 结果，核对实际数据截止日和质量记录。
4. 同版本本地快照可做逐点复算；供应商重新下载数据会修订，数值不一定完全相同。

## 下一周怎么更新

使用主周度程序时，复制最近一次的主周度 `config.json` 到新周一命名的目录。填写新的week、signal_date、reported_on及download_end_exclusive，保持已经冻结的评分方法和权重；end不包含当天。不要每周无条件重选“历史最优”参数。

用 `scripts/run_weekly.py --config 新周配置 --stage all` 下载并研究；保存新快照路径，后续离线用research。检查质量、公司去重、行业和事件风险，明确本周是否改变规则。

确认要归档后在同一研究命令加 `--publish`，再编写并复核周报。已有精选结果默认拒绝覆盖；同周追加实验沿用原周目录，完整运行产物保存在本地 outputs，对正式修订应保留Git变更说明。`--publish`不会提交或推送Git。

如果使用 `--study-weights`，保留候选集合、训练/复核区间、筛选标准、已查看数据等信息；结果只作研究，不会自动写回配置。真正改规则时另做验证并说明生效周。

最后仅提交代码变化和该周配置、报告及精选成果，正常推送main；不要 `git add .` 把本地数据一起加入。
